1.3. Обнаруженные gaps backend
  G1  Нет API чтения журнала аудита (таблица audit_log и право audit.read
      есть). Без него невозможны раздел «Аудит» и «последние изменения»
      на дашборде. → нужен GET /admin/audit (audit.read), минимально.
  G2  Нет сводки каталога: «товары без изображения», «без цены», сводка
      наличия не выводятся ни одним эндпоинтом (список товаров не содержит
      ни изображений, ни цен). → нужен read-only эндпоинт сводки (catalog.read).
  G3  Нет списка остатков по всем товарам: остатки читаются только по одному
      товару. Страница «Склад» без него требует N+1 запросов. → нужен
      read-only постраничный список остатков (catalog.read).
  G4  Пользователи: только список. Создания, изменения роли, отключения
      в backend НЕТ → раздел «Пользователи» только для чтения; управление —
      отдельное решение (не придумываем frontend-only RBAC).
      Матрица «роль → права» наружу не отдаётся (только свои права в /me).
  G5  Карточка заявки не показывает, пришла ли заявка из кабинета клиента
      (customer_id не в схеме). Не блокирует — фиксируем.
  Количество заявок по статусам берётся из GET /requests?status=…&page_size=1
  (поле total) — отдельный эндпоинт не нужен.
