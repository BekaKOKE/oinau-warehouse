# ADR-0001. Ведение ADR

**Статус:** Принято
**Дата:** 2026-09-09

## Контекст

Проект развивается этапами, между которыми проходит время. Причины решений
забываются, и позже кто-то «упрощает» схему, ломая заложенные ограничения.

## Решение

Каждое значимое архитектурное решение фиксируется отдельным файлом в
`docs/adr/`. Решение считается значимым, если его отмена потребует миграции
данных, изменения контракта API или переписывания более одного модуля.

ADR не редактируются задним числом: устаревший ADR помечается статусом
«Заменено ADR-NNNN».

## Последствия

Небольшие накладные расходы на написание. Взамен — воспроизводимый контекст
решений и защита от случайных откатов архитектуры.
