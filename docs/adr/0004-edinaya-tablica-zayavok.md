# ADR-0004. Одна таблица заявок вместо orders и leads

**Статус:** Принято
**Дата:** 2026-09-09

## Контекст

Требовались два сценария: заявка с корзиной товаров (CART) и обращение
из формы «Не нашли нужный товар?» (GENERAL). Напрашивалось разделение на
`orders` и `leads`.

## Решение

Одна таблица `requests` с полем `kind`. Позиции — в `request_items`,
у GENERAL-заявок их просто нет.

## Обоснование

У обеих сущностей полностью совпадают контактные поля, статусная модель,
воронка, комментарии, история статусов, уведомления, права доступа
и выгрузка в 1С. Отличается только наличие позиций.

Две таблицы означали бы: два набора статусов, которые разъедутся;
два экрана с почти одинаковым кодом; два отчёта, которые придётся
объединять; и постоянный вопрос «в какой таблице искать это обращение».

В админке это по-прежнему два раздела — с разным фильтром по `kind`.

## Последствия

Часть колонок у GENERAL-заявок остаётся пустой (`total_estimate`).
Это дешевле, чем дублирование схемы. Если появится тип заявки
с принципиально другим набором полей, он получит свою таблицу, а не
раздует эту.
