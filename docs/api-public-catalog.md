# Публичный каталог API

Базовый префикс: `/api/v1/public`. Авторизация не требуется.
Отдаются только товары со статусом `PUBLISHED`, `is_active = true`
и `deleted_at IS NULL`, и только активные неудалённые категории.

---

## Эндпоинты

| Метод | Путь                        | Назначение                                                   |
| ----- | --------------------------- | ------------------------------------------------------------ |
| GET   | `/categories`               | Дерево активных категорий                                    |
| GET   | `/categories/{slug}`        | Категория: описание, SEO, хлебные крошки, подкатегории       |
| GET   | `/categories/{slug}/facets` | Фильтры раздела: характеристики OPTION со счётчиками         |
| GET   | `/products`                 | Список товаров с фильтрами, поиском, сортировкой, пагинацией |
| GET   | `/products/{slug}`          | Карточка товара                                              |
| GET   | `/products/{slug}/related`  | Похожие товары (до 8)                                        |

### Параметры `/products`

| Параметр                 | Тип                                                                  | По умолчанию | Ограничение                                                |
| ------------------------ | -------------------------------------------------------------------- | ------------ | ---------------------------------------------------------- |
| `page`                   | int                                                                  | 1            | 1…10000                                                    |
| `page_size`              | int                                                                  | 24           | 1…60                                                       |
| `category`               | slug                                                                 | —            | товары раздела **и всех подразделов**                      |
| `search`                 | строка                                                               | —            | максимум 100 символов; пустая после `strip()` игнорируется |
| `availability`           | `IN_STOCK` / `OUT_OF_STOCK` / `ON_REQUEST`                           | —            |                                                            |
| `min_price`, `max_price` | decimal ≥ 0                                                          | —            | по минимальной цене товара                                 |
| `featured`               | bool                                                                 | —            |                                                            |
| `attr`                   | `код:slug`, повторяется                                              | —            | до 20; разные коды — «И», варианты одного кода — «ИЛИ»     |
| `sort`                   | `relevance` / `newest` / `price_asc` / `price_desc` / `name` / `sku` | `relevance`  | белый список                                               |
| `locale`                 | код языка                                                            | `ru`         | неизвестный → `ru`                                         |

Любое значение `sort` вне списка — `422`, а не молчаливый фолбэк:
опечатка в параметре должна быть заметна, а не приводить к другому
порядку выдачи.

`{slug}` во всех путях валидируется одной аннотацией:
`min_length=1`, `max_length=200`, `^[a-z0-9-]+$`. Некорректный slug даёт
`422` до обращения к БД.

## Контракты ответов

Схемы — `app/modules/catalog/schemas.py`. ORM-модели наружу не
отдаются: отдельные схемы фиксируют контракт и делают невозможной
утечку поля при добавлении колонки в модель.

### Список товаров

```jsonc
{
  "items": [
    {
      "sku": "KAN-16-PP",
      "slug": "kanat-16-pp",
      "name": "Канат полипропиленовый 16 мм",
      "short_description": "Армированный канат…",
      "unit": "m",
      "is_featured": true,
      "price": {
        "type": "TIERED",
        "currency": "KZT",
        "price": null,
        "from_price": "2600.00",
        "to_price": "3500.00",
        "tiers": [],
      },
      "availability": "IN_STOCK",
      "image": null,
    },
  ],
  "total": 3,
  "page": 1,
  "page_size": 24,
  "pages": 1,
}
```

Ступени в списке не передаются: странице каталога достаточно «от N ₸»,
а таблица ступеней на 24 позиции раздула бы ответ без пользы.

### Карточка товара

Дополнительно: `description`, `brand`, `min_order_qty`, `breadcrumbs`,
`categories`, `images[]`, `characteristics[]`, `specs`, `seo_title`,
`seo_description`, полный `price.tiers`.

Поля `status` в ответе нет: публичный API по определению отдаёт только
`PUBLISHED`-товары, поэтому статус не несёт информации.

### Деньги

Decimal сериализуется строкой (`"2600.00"`). Это осознанно: JSON-число
превратилось бы в float на стороне JS и потеряло бы копейки.

## Поиск

PostgreSQL, без Elasticsearch. Три механизма работают вместе, все —
на индексах, созданных на этапе 3; схема не менялась.

| Механизм                                             | Индекс                                          | Что даёт                                                |
| ---------------------------------------------------- | ----------------------------------------------- | ------------------------------------------------------- |
| `websearch_to_tsquery('russian')` по `search_vector` | GIN `ix_product_translations_search`            | Морфологический поиск: «канаты» находит «Канат»         |
| `ILIKE '%…%'` по `sku`                               | GIN trigram `ix_products_sku_trgm`              | Поиск по фрагменту артикула: «KRP-M» находит KRP-M10    |
| `ILIKE '%…%'` по `name`                              | GIN trigram `ix_product_translations_name_trgm` | Поиск по фрагменту названия, в том числе по части слова |

Разделение обязанностей: за морфологию отвечает **только** полнотекстовый
поиск, за поиск по подстроке — `ILIKE`. Trigram-индекс здесь ничего не
«исправляет»: он не делает поиск нечётким, а лишь позволяет выполнить
`ILIKE` с ведущим `%` по индексу, а не полным сканированием таблицы.
Совпадение по-прежнему должно быть точным вхождением подстроки —
запрос с опечаткой («канта» вместо «канат») ничего не найдёт.

Нечёткий поиск по схожести (`similarity()` / оператор `%` из pg_trgm)
не включён намеренно: он требует подбора порога и даёт ложные
срабатывания на коротких артикулах. Вопрос стоит поднять, когда на
реальных запросах станет видно, сколько поисков заканчивается пустой
выдачей.

Условия объединяются через `OR`. При `sort=relevance` порядок задаёт
`ts_rank_cd`; без поискового запроса релевантность вырождается
в «сначала избранные, потом новые». Строка из одних пробелов
приравнивается к отсутствию поиска.

`search_vector` — генерируемая колонка PostgreSQL, поэтому
рассинхронизация индекса с данными невозможна в принципе.

## Цены

Используется **только прайс-лист с `is_default = true`**. Дилерские и
партнёрские прайсы публичному API неизвестны: ступени грузятся
отдельным запросом с явным `price_list_id`, а не через связь
`Product.price_tiers`, которая подтянула бы все прайс-листы и оставила
защиту на аккуратности фильтрации в Python.

| `pricing_type` | `price` | `from_price` | `tiers`      |
| -------------- | ------- | ------------ | ------------ |
| `FIXED`        | цена    | она же       | одна ступень |
| `TIERED`       | `null`  | минимальная  | все ступени  |
| `FROM`         | `null`  | минимальная  | все ступени  |
| `ON_REQUEST`   | `null`  | `null`       | `[]`         |

`max_quantity: null` в ступени означает открытый диапазон «и выше»
(верхняя ступень 100+).

Товар без единой строки в публичном прайсе показывается как
`ON_REQUEST`, даже если помечен иначе: пустое место вместо цены хуже
честной кнопки «Запросить цену».

## Наличие

Точное количество наружу не отдаётся никогда — по нему конкурент
оценивает обороты. Публичный API знает три состояния; расчёт —
`app/modules/inventory/availability.py`.

Приоритет:

1. `products.stock_display_override` — ручное решение менеджера
   (ожидается поставка, позиция снята с продажи).
2. `pricing_type = ON_REQUEST` → `ON_REQUEST`.
3. Сумма `quantity - reserved` по **активным** складам: `> 0` →
   `IN_STOCK`, иначе `OUT_OF_STOCK`.

Фильтр `availability` повторяет эту логику в SQL. Дублирование
неизбежно: вычислять статус построчно в Python нельзя, потому что по
нему надо фильтровать и считать `total`. Обе ветки закрыты тестами.

## Локализация

`locale` — параметр запроса, а не только `Accept-Language`: язык должен
переключаться ссылкой и попадать в URL, иначе поисковые системы не
увидят вторую языковую версию.

Запрос выполняет два `LEFT JOIN` к `product_translations` — на
запрошенную локаль и на локаль по умолчанию — и берёт
`COALESCE(запрошенная, запасная)`. Добавление казахского не потребует
менять ни один эндпоинт: строки без перевода автоматически покажутся
по-русски. Неподдерживаемая локаль не ошибка — отдаётся `ru`.

Названия характеристик и подписи вариантов живут в JSONB `name_i18n` /
`value_i18n` и выбираются по тому же правилу.

## Изображения

Возвращаются только файлы со статусом `READY`: ссылка на необработанную
загрузку вела бы в 404. URL собирается как `CDN_BASE_URL + storage_key`
существующей функцией `build_public_url()` — выдуманных production-URL
в коде нет.

Наружу уходит только готовый `url`. Внутренний `storage_key` в ответе
не публикуется: фронтенду он не нужен, а раскрывать структуру бакета
незачем.

С этапа 5D `url` ведёт на WebP-вариант `large`, в `variants` — все
варианты (`large`, `medium`, `small`, `thumb`), `width`/`height` — размер
файла по `url`. Оригинал в ответ не попадает. Товар без готовых
изображений отдаёт `images: []` — это корректное состояние, а не ошибка.
Подробнее — `docs/api-media-content.md`.

## Таблица товаров раздела (B2B)

Строка списка (`ProductListItem`) несёт всё, что нужно таблице раздела:
`price.tiers` (ступени публичного прайса — одним запросом на страницу),
`characteristics` (видимые характеристики), `specs`, `min_order_qty`.
Точный остаток по-прежнему не отдаётся — только статус `availability`.

## Схемы и чертежи

`ProductDetail.documents` — схемы и чертежи отдельно от галереи:
`{url, kind, filename, content_type, size_bytes, preview_url}`. В
`images` роли `SCHEME`/`DRAWING` и документы (PDF, DWG, DXF) больше не
попадают. У PDF `url` открывается в браузере, у DWG/DXF — скачивание
(заголовок CDN), у схемы-изображения есть `preview_url`.

## Производительность

Список товаров — **фиксированное число запросов независимо от размера
страницы**:

1. `COUNT` для пагинации;
2. основной `SELECT` с агрегатами цены и остатка (два подзапроса
   `GROUP BY`, подключённые через `LEFT JOIN`);
3. `selectinload` изображений вместе с `media_files`.

Тест `test_product_list_has_no_n_plus_one` сравнивает счётчик SQL для
3 и 15 товаров — при появлении запроса на каждый товар он падает.

Кеширование не добавлено намеренно: сначала корректный запрос
к PostgreSQL. Каталог такого размера отдаётся из shared buffers,
и Redis перед ним только добавил бы инвалидацию как новый источник
ошибок. Возвращаться к вопросу имеет смысл, когда появится реальный
трафик и станет видно, какой эндпоинт того стоит.

## Ограничения

- Пагинация по смещению, а не курсорная (обоснование —
  `app/core/pagination.py`). Порог пересмотра: десятки тысяч товаров
  или бесконечная прокрутка.
- Сортировка по названию использует порядок сортировки БД; база создана
  с `--locale=C`, поэтому кириллица сортируется по кодам символов.
  Для витрины это заметно на смешанных латинско-кириллических
  названиях; лечится `COLLATE "ru-RU-x-icu"` при необходимости.
- Фасетных счётчиков в фильтрах пока нет.
