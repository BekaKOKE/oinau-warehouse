# Excel: импорт и экспорт каталога (этап 5E)

Массовое управление каталогом через XLSX: товары, категории,
характеристики и их значения, цены, минимальная партия, основные свойства.
Один канонический формат для экспорта и импорта: выгруженный файл можно
отредактировать в Excel и вернуть импортом без ручного преобразования.

**Остатки через Excel не выгружаются и не загружаются.** Источник истины по
складу — 1С (будущая интеграция). Артикул (`sku`) — стабильный ключ товара,
по которому будет идти и сопоставление с 1С.

Код: `apps/backend/app/modules/imports/`.

## Эндпоинты

| Метод | Путь                                                                      | Право                       |
| ----- | ------------------------------------------------------------------------- | --------------------------- |
| GET   | `/api/v1/admin/catalog/export` — книга XLSX                               | `catalog.read`              |
| GET   | `/api/v1/admin/catalog/imports/template` — пустой шаблон                  | `catalog.read`              |
| POST  | `/api/v1/admin/catalog/imports/preview` — multipart, поле `file`          | `catalog.read`, rate limit  |
| POST  | `/api/v1/admin/catalog/imports/{uuid}/commit` — multipart, тот же файл    | `catalog.write`, rate limit |
| GET   | `/api/v1/admin/catalog/imports` (`status`, `page`, `page_size`) — история | `catalog.read`              |
| GET   | `/api/v1/admin/catalog/imports/{uuid}` — импорт с ошибками                | `catalog.read`              |

Права — из существующей матрицы, новых не вводилось. Предпросмотр каталог
не меняет, поэтому доступен с `catalog.read` (проверить файл может любой
сотрудник с доступом к каталогу). Применить — только `catalog.write`:
SUPERADMIN, ADMIN, CONTENT_MANAGER. У MANAGER и VIEWER права записи нет —
подтверждение для них 403.

## Порядок работы

```
1. GET  /catalog/export                     -> catalog.xlsx
2. правка в Excel
3. POST /catalog/imports/preview   file=... -> отчёт: valid, счётчики, ошибки
                                               (лист, строка, колонка), что изменится
                                               каталог НЕ меняется; запись в import_jobs
4. POST /catalog/imports/{uuid}/commit  file=тот же файл
        -> сверка SHA-256 с предпросмотром
        -> advisory-блокировка импорта, блокировка строк товаров из файла
        -> повторная проверка по свежему состоянию каталога
        -> применение одной транзакцией (всё или ничего)
```

Предпросмотр живёт `IMPORT_PREVIEW_TTL_HOURS` (24 ч). Статусы импорта:

| Статус      | Значение                                                                         |
| ----------- | -------------------------------------------------------------------------------- |
| `VALID`     | предпросмотр без ошибок, можно подтверждать (`can_commit=true`)                  |
| `INVALID`   | в файле ошибки — подтверждение невозможно                                        |
| `COMMITTED` | применён (конечный)                                                              |
| `FAILED`    | подтверждение отклонено повторной проверкой или базой (конечный, `failure_code`) |

Ответы подтверждения: `200` — применено; `409 import_already_committed` —
повтор (идемпотентность: второй раз не применяется); `409 import_not_valid`,
`import_failed`, `import_preview_expired`; `409 import_file_mismatch` — файл
отличается от проверенного (импорт остаётся `VALID`); `422
import_validation_failed` — каталог изменился после предпросмотра (в `details`
— первые 50 ошибок, все — в истории); `409 sku_exists` / `product_slug_exists`
/ ... — гонка, пойманная уникальным индексом базы (транзакция откачена).

Ошибки данных возвращаются в предпросмотре со статусом `200` и `valid=false`:

```json
{
  "sheet": "Prices",
  "row": 7,
  "column": "price",
  "code": "invalid_value",
  "message": "Не больше 2 знаков после запятой",
  "value": "1200.555"
}
```

`row` — номер строки Excel (заголовок — строка 1). Отчёт хранит до 500
ошибок (`error_count` — полное число). Отказ принять файл целиком — ошибкой
в едином формате: `413 import_file_too_large`, `415 import_unsupported_file`,
`422 import_file_corrupted`, `422 import_file_empty`, `422 import_file_missing`,
`400 import_upload_invalid`.

## Формат XLSX (версия 1)

Листы: `Products`, `Prices`, `ProductAttributes`, `ProductSpecs`, `Categories`,
`CategoryAttributes`, `Attributes`, `AttributeOptions` (все обязательны, могут
быть пустыми) и `README` (инструкция, импортом не читается). Другие листы
пропускаются.

Заголовок — первая строка. Порядок колонок любой, регистр не важен. Все
колонки обязательны; колонки переводов на дополнительные локали
(`name_kk`, ...) — по мере включения языка в `SUPPORTED_LOCALES`, набором
целиком. Неизвестная колонка — ошибка (опечатка не должна молча
игнорироваться); колонки-пометки начинайте с `#` — они пропускаются.
Пустые строки пропускаются.

### Products — товар, ключ `sku`

| Колонка                                                                        | Значение                                                       |
| ------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| `sku`                                                                          | артикул: `A-Z a-z 0-9 . _ / -`, до 64                          |
| `slug`                                                                         | `a-z 0-9 -`, уникален среди живых товаров                      |
| `name_ru`                                                                      | название                                                       |
| `status`                                                                       | `DRAFT` / `PUBLISHED` / `ARCHIVED`                             |
| `is_active`, `is_featured`                                                     | TRUE/FALSE (также 1/0, да/нет)                                 |
| `categories`                                                                   | slug категорий через `;`, первая — основная (канонический URL) |
| `unit`                                                                         | единица (`pcs`, `m`, ... — без справочника, как в модели)      |
| `min_order_qty`                                                                | > 0, до 3 знаков                                               |
| `pricing_type`                                                                 | `FIXED` / `FROM` / `TIERED` / `ON_REQUEST`                     |
| `brand`, `external_id`                                                         | необязательные значения (пусто = NULL)                         |
| `short_description_ru`, `description_ru`, `seo_title_ru`, `seo_description_ru` | тексты                                                         |

### Prices — ступень публичного прайс-листа

`sku`, `min_qty` (> 0, до 3 знаков), `max_qty` (пусто = «и выше»), `price`
(≥ 0, до 2 знаков). Правила — те же, что у `PUT /products/{id}/pricing`
(`PricingUpdate`): FIXED — одна ступень `1..∞`; FROM/TIERED — от 1 до 20
ступеней без пересечений (границы включающие); ON_REQUEST — без ступеней.
Валюта — валюта прайс-листа по умолчанию. Дилерские прайсы импорт не трогает.

### ProductAttributes — значение характеристики

`sku`, `attribute_code`, `value`. Значение разбирается по типу
характеристики: STRING — текст до 255; NUMBER — число до 3 знаков;
BOOLEAN — TRUE/FALSE; OPTION — slug варианта **этой** характеристики
(несколько вариантов — несколько строк). Скалярная характеристика —
одно значение на товар.

### ProductSpecs — описательные характеристики карточки

`sku`, `name` (до 120), `value` (до 500). До 50 на товар.

### Categories — категория, ключ `slug`

`slug`, `parent_slug` (пусто — корень), `name_ru`, `sort_order`, `is_active`,
`external_id`, `description_ru`, `seo_title_ru`, `seo_description_ru`.
Родитель — живая категория из каталога или из этого же листа. Цикл и
«сам себе родитель» — ошибка. Материализованный путь перенесённых веток
пересчитывается.

### CategoryAttributes — фильтры категории

`category_slug` (категория с листа Categories), `attribute_code`,
`sort_order`, `is_required`.

### Attributes — характеристика, ключ `code`

`code` (`a-z 0-9 _`), `value_type` (`STRING`/`NUMBER`/`BOOLEAN`/`OPTION`),
`name_ru`, `unit`, `is_filterable`, `is_visible`, `is_active`, `sort_order`.
Тип существующей характеристики менять нельзя (как в Admin API).

### AttributeOptions — вариант значения, ключ `attribute_code` + `slug`

`attribute_code` (тип OPTION), `slug`, `value_ru`, `sort_order`.

## Правила применения

- **Ничего не удаляется.** Товары, категории, характеристики, которых нет
  в файле, не трогаются.
- **Сущность из файла — создаётся или обновляется** по ключу. Товар — по
  `sku` среди живых (удалённый товар артикул не занимает — будет создан
  новый, с предупреждением).
- **Связи сущности из файла заменяются целиком**: у товара — категории,
  цены, характеристики, описательные характеристики; у категории — фильтры.
  Удалили строку — удалилось значение. Предпросмотр показывает, какие части
  каждого товара изменятся (`changes[].changed`).
- **Строки дочерних листов — только для сущностей из главного листа**
  (цена товара, которого нет на листе Products, — ошибка).
- **Неизменённые данные не трогаются**: без записи, без `updated_at`, без
  аудита. Неизменная цена не перепроверяется (старые данные не блокируют
  импорт остального). Возврат неизменённой выгрузки — ноль изменений.
- **Переводы** дополняются по локалям (как в Admin API); пустая ячейка
  текста — пустое поле.
- **`sync_source='excel'`** у записанных импортом товаров, категорий и ступеней.

### Артикул

`sku` — неизменяемый ключ сопоставления. Переименовать артикул импортом
нельзя: новый артикул означает новый товар. Попытка «переименовать» с тем
же `slug` упирается в занятый slug (`slug_taken`) — случайного превращения
одного товара в другой не происходит. Смена артикула — `PATCH /products/{id}`.
Артикулы, отличающиеся только регистром (`kan-16` и `KAN-16`), — ошибка:
почти всегда это опечатка, которая создала бы дубль.

Обмен ключами между двумя товарами в одном файле (slug A ↔ slug B)
отклоняется — выполните в два импорта.

## Безопасность

- Тело читается вручную ПОСЛЕ проверки прав (анонимный клиент не может
  загрузить мегабайты до 401) с лимитом `UPLOAD_MAX_SIZE_MB` по мере
  чтения, даже без Content-Length. Файл — в памяти; временные файлы парсера
  multipart закрываются сразу. На диск и в хранилище ничего не пишется.
- Тип — по содержимому: сигнатура ZIP, части `[Content_Types].xml` и
  `xl/workbook.xml`, тип основной части `spreadsheetml.sheet.main+xml`.
  Отвергаются `.xls`, CSV, `.xlsm` (макросы, `vbaProject.bin`), шаблоны,
  зашифрованные книги. Расширение и заявленный тип — только первое сито.
- ZIP-бомба: суммарный распакованный размер ≤ `IMPORT_MAX_UNCOMPRESSED_MB`,
  не больше 1000 частей, пути `..` и абсолютные — отказ.
- XML — через defusedxml (XXE и «billion laughs» запрещены).
- Формулы не вычисляются и не принимаются: ячейка с формулой — ошибка.
  Ошибки Excel (`#N/A`) и даты — ошибка.
- Тексты — простой текст по общим правилам (`app/core/text.py`): без HTML,
  управляющих символов и bidi-override. Все значения проходят Pydantic-схемы
  Admin API (`ProductCreate`, `CategoryCreate`, `AttributeCreate`,
  `AttributeOptionCreate`, `PricingUpdate`).
- Имя файла — только для истории (последний компонент пути, без
  управляющих символов). В журнал и в историю содержимое файла не пишется.
- Rate limit `RATE_LIMIT_CATALOG_IMPORT` на предпросмотр и подтверждение.

### Formula injection при экспорте

Текст пишется только строковой ячейкой (тип `s`), даже если похож на
формулу или код ошибки. Строкам, начинающимся с `= + - @` (и табуляции),
ставится `quotePrefix` — Excel показывает их как текст и не пересчитывает
даже после редактирования. Значение при этом не меняется (апостроф в данные
не добавляется), поэтому round-trip точный.

### Decimal

Числа Excel — float. Decimal строится из `repr(float)` (кратчайшее
десятичное представление), а не из float: `0.1` -> `0.1`, а не
`0.1000000000000000055…`. Лишние знаки отвергаются, а не округляются.
Текст `1 200,50` тоже принимается.

## История и аудит

`import_jobs`: kind, status, filename, file_size, file_sha256, rows_total,
products_created/updated/unchanged (план на предпросмотре, факт после
подтверждения), error_count, warning_count, summary/errors/warnings (JSONB),
created_by_id, committed_by_id, committed_at, failure_code.

Аудит: `catalog_import.previewed`, `catalog_import.committed`,
`catalog_import.commit_failed` (entity `import_job`, только метаданные и
счётчики). Изменения сущностей — теми же действиями, что Admin API
(`catalog.product_created`, `catalog.product_updated`,
`catalog.product_categories_replaced`, `catalog.product_attributes_replaced`,
`pricing.updated`, `catalog.category_*`, `catalog.attribute_*`,
`catalog.attribute_option_*`, `catalog.category_attributes_assigned`) с
`actor="import"` и `changes.import_job=<uuid>`.

## Производительность

Проверка файла идёт в памяти по снимку каталога, загруженному
фиксированным числом запросов (справочники целиком, товары — только из
файла). Запись связей — пакетно: один DELETE на тип связи для всех товаров
файла, затем INSERT. Число запросов предпросмотра и экспорта не зависит от
числа строк (есть тесты). Разбор и сборка книги — в пуле потоков.

Подтверждение синхронное: для каталога в сотни–тысячи позиций это доли
секунды–секунды. Если понадобится воркер, контракт не меняется: файл
кладётся в приватный префикс хранилища (`imports/{job_uuid}.xlsx`), воркер
вызывает тот же код применения.

## Ограничения

- Остатки, изображения и `stock_display_override` через Excel не
  управляются; `weight_kg` в формат не входит (его нет и в Admin API).
- Импорт не удаляет сущности и не восстанавливает удалённые.
- Переименование артикула и slug категории/код характеристики — только
  через Admin API.
- Файл на подтверждение отправляется повторно (сервер его не хранит).
- Цены — только публичный прайс-лист по умолчанию.

## Массовый импорт товаров (ZIP)

Менеджер готовит каталог в Excel и одним архивом загружает товары вместе
с фотографиями и схемами. Это отдельный режим: обычный импорт XLSX
(выше) работает как раньше.

Код: `apps/backend/app/modules/imports/bundle_*.py`, `router_bundle.py`,
задачи воркера — `app/workers/tasks/imports.py`.

### Структура архива

```
bundle.zip
    products.xlsx          книга (лист «Товары», «Products» или первый лист)
    photos/
        504-176.jpg
        504-176-2.jpg
        1639000R.jpg
    schemes/
        504-176.pdf
        1639000R.jpg
```

- Книга — в корне архива или в одной общей папке («архив папки целиком»).
- Папки можно назвать и по-русски: `фото/`, `схемы/`, `чертежи/`.
- Фото: jpg, jpeg, png, webp (до `UPLOAD_MAX_SIZE_MB`). Схемы: pdf, dwg,
  dxf, jpg, png, webp (до `UPLOAD_MAX_DOCUMENT_SIZE_MB`).
- Файлы вне `photos/` и `schemes/`, а также не указанные в книге —
  предупреждение, не загружаются. `__MACOSX/`, `.DS_Store`, `Thumbs.db`
  пропускаются молча.

### Книга

Тот же канонический формат, что у обычного импорта, с послаблениями:

- обязателен только лист товаров, остальные листы (Prices, ProductSpecs,
  Categories, ...) необязательны — отсутствующий лист не меняет эту часть;
- на листе товаров обязателен только **артикул**; у нового товара — ещё
  название;
- **пустая ячейка или отсутствующая колонка — «не менять»**. У нового
  товара — значения по умолчанию: опубликован, активен, `pcs`,
  минимальная партия 1, цена по запросу;
- заголовки можно писать по-русски:

| Колонка                            | Значение                                                                        |
| ---------------------------------- | ------------------------------------------------------------------------------- |
| Артикул                            | ключ товара (`sku`)                                                             |
| Название / Наименование            | `name_ru`                                                                       |
| slug                               | необязательно; у нового товара — из названия и артикула                         |
| Категория                          | slug, название или путь «Раздел / Подраздел»; несколько — через `;`             |
| Описание, Краткое описание         | тексты                                                                          |
| Цена                               | одна цена → тип FIXED                                                           |
| Цена от N                          | ступени по количеству: «Цена от 1», «Цена от 100», ... → тип TIERED             |
| Тип цены                           | необязательно: FIXED / FROM / TIERED / ON_REQUEST                               |
| Валюта                             | только валюта прайс-листа (KZT)                                                 |
| Остаток, Резерв                    | количество на складе по умолчанию (первый активный), `sync_source=excel`        |
| Фото                               | имена файлов из `photos/` через `;` или колонки «Фото 1», «Фото 2», ...         |
| Схема                              | имена файлов из `schemes/` через `;`                                            |
| хар: Название                      | описательная характеристика («хар: Цвет»)                                       |
| Характеристики                     | «Цвет: чёрный; Материал: резина»                                                |
| attr:код                           | значение характеристики-фильтра; OPTION — slug или название варианта, через `;` |
| Код 1С, Активен, Избранное, Статус | `external_id`, `is_active`, `is_featured`, `status`                             |

Колонки «Цена от 1 / 100 / 1000» превращаются в ступени без разрывов:
`[1; 99.999]`, `[100; 999.999]`, `[1000; ∞)` — существующая модель
`price_tiers`, новой таблицы цен нет. Цены и остатки заданы и колонками,
и отдельным листом — ошибка.

### Фото и схемы

- Заполненная ячейка «Фото» — **полный набор** фото товара в указанном
  порядке; первое — обложка. Привязки, которых нет в списке, снимаются
  (файлы остаются в медиатеке). Пустая ячейка — фото не меняются.
- Файл, уже привязанный к товару, повторно не загружается: совпадение по
  SHA-256 или, если файла нет в архиве, по имени. Поэтому при повторном
  импорте старые фото можно не класть в архив — достаточно имени.
- Файл с тем же содержимым, что уже есть в медиатеке, не загружается
  второй раз. Один файл у нескольких товаров загружается один раз.
- Тот же файл с новым содержимым (новая редакция схемы) — новый файл
  медиатеки, старая привязка снимается.
- Схема — привязка с ролью `SCHEME`, в галерею фото не попадает.
  На витрине — отдельное поле `documents` карточки товара.
- Файлы проходят существующий конвейер медиатеки: оригинал — в приватном
  `products/{uuid}/original.*`, изображения → WebP-варианты, документ →
  публичная копия `variants/file.<ext>` (PDF открывается в браузере,
  DWG/DXF скачиваются). Содержимое документов не интерпретируется.

### Поток и эндпоинты

Права: история, статус, отчёт, шаблон и пример — `catalog.read`;
загрузка, проверка, применение и отмена — `catalog.write` + `media.upload`.

| Метод  | Путь (`/api/v1/admin/catalog/bundle-imports`) | Что делает                                            |
| ------ | --------------------------------------------- | ----------------------------------------------------- |
| GET    | `/template`                                   | шаблон книги (лист «Товары», пример, README)          |
| GET    | `/example`                                    | рабочий пример архива                                 |
| POST   | `` (`{filename, size_bytes}`)                 | задача UPLOADING + presigned PUT на `imports/{uuid}/` |
| POST   | `/{uuid}/check`                               | архив загружен → CHECKING, задача воркеру             |
| GET    | `/{uuid}`                                     | статус, сводка, ошибки, предупреждения, изменения     |
| POST   | `/{uuid}/commit`                              | VALID → APPLYING, задача воркеру                      |
| DELETE | `/{uuid}`                                     | отмена до применения, архив удаляется                 |
| GET    | `/{uuid}/report`                              | отчёт XLSX: итог, ошибки, предупреждения, товары      |
| GET    | ``                                            | история ZIP-импортов                                  |

```
UPLOADING --check--> CHECKING --воркер--> VALID | INVALID
VALID --commit--> APPLYING --воркер--> COMMITTED | FAILED
UPLOADING | CHECKING | VALID | INVALID --DELETE--> CANCELLED
```

Применение: воркер скачивает архив во временный каталог, повторно
проверяет его, загружает новые файлы в хранилище, затем под
advisory-блокировкой импорта проверяет ещё раз по свежему состоянию
каталога и одной транзакцией пишет товары, цены, остатки и привязки
файлов. Любой сбой — откат транзакции, загруженные файлы удаляются,
задача FAILED. После коммита новые файлы ставятся в очередь обработки,
архив удаляется. Непримененный архив удаляется через
`IMPORT_PREVIEW_TTL_HOURS` (cron воркера), зависшая задача помечается
FAILED через 2 часа.

Локально без воркера: `IMPORT_BUNDLE_INLINE=true` — проверка и
применение выполняются прямо в запросе.

### Безопасность архива

- архив идёт браузером прямо в приватный префикс хранилища, а не через
  API: лимит тела запроса на прокси не мешает, API не держит сотни
  мегабайт в памяти;
- фактический размер архива проверяется по хранилищу (presigned PUT его
  не ограничивает), скачивание прерывается на `IMPORT_BUNDLE_MAX_MB`;
- пути: абсолютные, с буквой диска, с `..`, пустыми сегментами и
  управляющими символами — отказ всему архиву. Ничего не распаковывается
  на диск по именам из архива: файлы читаются из ZIP в память по одному;
- символические ссылки и зашифрованные архивы — отказ;
- ZIP-бомба: число файлов, суммарный распакованный размер и степень
  сжатия каждого файла ограничены до чтения содержимого;
- тип файла — по сигнатуре содержимого (JPEG/PNG/WebP/PDF/DWG/DXF), у
  изображений Pillow проверяет структуру и число пикселей;
- книга — тем же разбором, что обычный XLSX: без макросов, формулы
  отвергаются, XML через defusedxml;
- имена в кодировке cp866 (архиватор Windows без флага UTF-8)
  декодируются корректно;
- временный каталог удаляется после обработки.
