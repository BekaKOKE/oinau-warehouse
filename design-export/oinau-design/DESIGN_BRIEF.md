# OINAU PRO — дизайн витрины для переработки

Сайт-каталог комплектующих для детских площадок (Казахстан, B2B: производители,
монтажники, муниципальные проекты). Корзины и оплаты нет: пользователь собирает
**заявку** и отправляет её менеджеру.

Задача: улучшить визуальный дизайн существующих страниц. Структура, контент
и функции остаются, меняется оформление.

## Что в архиве

| Папка / файл | Что это |
|---|---|
| `index.html` | Оглавление: открыть в браузере, оттуда ссылки на все страницы |
| `pages/*.html` | Статичные копии страниц (открываются без сервера) |
| `css/*.css` | Весь CSS страницы одним файлом (так его отдал браузер) |
| `screenshots/` | Скриншоты во всю высоту: ПК 1440 px и телефон 390 px |
| `tokens.css` | Дизайн-токены: цвета, радиусы, тени, отступы, шрифты |
| `source/` | Исходники: React-компоненты (`.tsx`) и CSS-модули (`.module.css`) |
| `assets/` | Фото hero и шрифты |

Имена классов в `pages/*.html` вида `Hero_title__AbC12` — это класс `title`
из файла `source/components/home/Hero.module.css`. Правьте удобнее всего `source/`.

## Страницы

| Файл | Страница |
|---|---|
| `home.html` | Главная: hero с фото и метками, разделы каталога, промо-карточки, популярные товары, преимущества, о компании |
| `catalog.html` | Каталог: фильтры, сортировка, сетка товаров |
| `category.html` | Раздел каталога |
| `product.html` | Карточка товара: цена, объёмные цены, количество, «Добавить в заявку» |
| `delivery.html`, `faq.html`, `contacts.html` | Контентные страницы |
| `favorites.html` | Избранное |
| `cabinet-login.html` | Заглушка личного кабинета |

Фото товаров в копии заменены плейсхолдером — это нормально, настоящие фото
приходят из медиатеки.

## Текущий стиль

- Шрифты: **Manrope** (основной) и **IBM Plex Mono** (подписи, артикулы, мелкий капс).
- Тёмный navy `#0e1620` для шапки и hero, светлый тёплый фон `#f4f3f0` для остального.
- Акцент: синий `#0b5fd0` / светлый `#7fb4ff`.
- Все значения — в `tokens.css`. Новые цвета/отступы лучше заводить там же как токены.

## Что нельзя ломать (обязательно)

1. **Hero-фото и метки на нём.** Фото `assets/img/playground.webp` 1536×1024 (3:2).
   Метки («Крыша», «Горка», …) стоят в процентах от размеров фото
   (`source/lib/hotspots.ts`). Поэтому:
   - кадр фото должен сохранять пропорцию **3:2** и не обрезаться (`object-fit: cover` при другой пропорции уведёт метки с объектов);
   - метки — ссылки, они должны быть **поверх** всех декоративных слоёв и нажиматься;
   - края фото сейчас растворяются в фоне маской (`mask-image`) — это желаемое поведение, его можно улучшать, но не возвращать рамку-прямоугольник.
2. **Контент не выдумывать.** Заголовки hero, тексты FAQ/доставки/контактов приходят из CMS,
   цифры («20 позиций», «9 разделов») считаются из каталога. Новые цифры, отзывы,
   логотипы клиентов не добавлять — можно оставить место под них с пометкой.
3. **Доступность.** Кликабельные элементы не меньше 44×44 px, контраст текста AA,
   видимый фокус с клавиатуры, анимации уважают `prefers-reduced-motion`.
4. **Адаптивность.** Всё должно работать от 360 px. Сейчас используются брейкпоинты
   1180, 1040, 960, 860, 720, 640, 560, 520 px (главные — 1180 / 860 / 720).
   На узком экране метки на фото превращаются в точки, а разделы уходят
   в горизонтальный ряд под фото — логику можно менять, но разделы должны
   оставаться доступны пальцем.
5. **Без тяжёлых зависимостей.** Проект на Next.js + CSS Modules. Без Tailwind,
   UI-китов и JS-анимационных библиотек — только CSS.

## Что вернуть

Предпочтительно — в том же виде, что пришло:

- изменённые файлы из `source/` (те же пути и имена, `.module.css` и при необходимости `.tsx`), и/или
- обновлённые `pages/*.html` + `css/*.css`, если удобнее работать со статикой,
- изменённый `tokens.css`,
- скриншоты нового варианта (ПК и телефон) — чтобы сверить результат.

Если меняется разметка (не только стили) — оставьте короткий список: что и зачем.
